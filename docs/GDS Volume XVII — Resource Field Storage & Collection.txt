# GDS: Resource Field Storage & Collection

## Overview

Resource production occurs continuously within each Resource Field. Unlike resources stored in the city's central stockpile, newly produced resources remain physically stored at the Resource Field until collected manually by the player or automatically by the Auto Collection system.

Each Resource Field functions as an independent storage location with a finite capacity based on its production rate.

---

## Field Storage Capacity

Each Resource Field can accumulate up to **sixteen (16) hours** of production.

Storage capacity is calculated dynamically:

$$\text{Field Storage Capacity} = \text{Hourly Production} \times 16$$

### Field Capacity Examples

| Resource Type | Hourly Production | Maximum Field Storage |
| --- | --- | --- |
| **Food** | 250 / hour | 4,000 Food |
| **Wood** | 600 / hour | 9,600 Wood |
| **Stone** | 1,200 / hour | 19,200 Stone |
| **Iron** | 2,500 / hour | 40,000 Iron |

Because maximum storage is based on current hourly production, upgrades, research, hero bonuses, and other modifiers automatically scale the total amount that can be stored in the field.

---

## Production Halt

Once a Resource Field reaches 100% of its maximum storage capacity:

1. **Production immediately halts.** No additional resources are generated by that field.
2. **Workers become idle** until storage space is freed.
3. **Production automatically resumes** as soon as resources are collected and field storage drops below capacity.

This mechanic prevents unlimited offline accumulation while allowing players to stay away from the game for up to 16 hours without losing production.

---

## Resource Collection & Stockpile

Resources stored inside Resource Fields cannot be directly used for construction, research, troop training, or trading. They must first be transferred into the city's central stockpile.

Collection occurs through either:

* **Manual Collection:** Initiated on demand by the player.
* **Auto Collection:** Triggered automatically by workers once fields reach threshold capacity.

---

## Auto Collection System

Beginning at **Town Hall Level 6**, players may enable the Auto Collection system.

### Trigger Threshold & Bottlenecks

* **90% Capacity Trigger:** Auto Collection triggers automatically whenever a Resource Field reaches **90% of its maximum capacity** ($\text{Hourly Production} \times 16 \times 0.90$). It then transfers resources into the city's central stockpile.
* **Warehouse / Central Stockpile Capacity Bottleneck:** If the city's central stockpile is completely full (at maximum Warehouse/Stockpile capacity), **Auto Collection pauses**. Reserved workers cannot deposit resources.
* While Auto Collection is paused due to a full stockpile, resources continue to accumulate in the field up to 100% capacity, at which point field production halts normally.



### Worker Requirements & Cooldowns

Auto Collection requires a dedicated workforce commitment based on Town Hall level:

| Town Hall Level | Workers Reserved |
| --- | --- |
| **Level 6** | 600 Workers |
| **Level 7** | 700 Workers |
| **Level 8** | 800 Workers |
| **Level 9** | 900 Workers |
| **Level 10** | 1,000 Workers |

* **Recovery Cooldown:** Disabling Auto Collection initiates a **3-hour recovery period** before those reserved workers become available for reassignment to other tasks.

---

## System State Summary

| Field Storage Level | Central Stockpile Status | Auto Collection Action | Field Production |
| --- | --- | --- | --- |
| **0% – 89%** | Any | Idle (Awaiting 90% threshold) | Active |
| **90% – 99%** | Space Available | **Transfers resources to stockpile** | Active |
| **90% – 99%** | **Full** | **PAUSED** (No room in stockpile) | Active |
| **100%** | **Full** | **PAUSED** | **HALTED** (Field Capped) |

---

## Raiding and Resource Protection

Resource security is split across two locations:

### 1. Resource Fields

* Resources stored inside Resource Fields are **completely unprotected**.
* During an enemy raid, uncollected resources in fields can be plundered independently per field.
* **Warehouse protection NEVER applies to resources inside fields.**
* Uncollected resources represent an economic risk in exchange for reduced micromanagement.

### 2. Central City Stockpile

* Collected resources are stored in the city's central stockpile and can be used immediately for game actions.
* The **Warehouse** protects central stockpile resources up to its protected capacity level.
* Any stockpile resources exceeding the Warehouse's protected limit remain vulnerable to plunder during attacks.

---

## Resource State Comparison Matrix

| Resource Location / State | Available for Use? | Protected by Warehouse? | Vulnerable to Raids? |
| --- | --- | --- | --- |
| **Stored in Resource Field** | No | No | **Yes** |
| **Stockpile (Within Warehouse Cap)** | Yes | **Yes** | No |
| **Stockpile (Exceeding Warehouse Cap)** | Yes | No | **Yes** |

---

## Strategic Implications

This mechanics balance introduces meaningful strategic decision-making:

1. **Frequent Manual Collection:** Reduces field exposure during raids but pushes central stockpile levels past Warehouse limits, making the city an attractive raiding target unless resources are spent immediately.
2. **Delayed Collection:** Keeps central stockpile levels safe under Warehouse caps, but risks losing accumulated field production to enemy raids or hitting the 16-hour field cap and halting production.
3. **Auto Collection Convenience vs. Risk:** Auto Collection automates upkeep and avoids field capping at 90%, but permanently reserves workers, and will continuously dump resources into the central stockpile—where amounts exceeding Warehouse protection become vulnerable to attacks. If stockpiles fill up completely, Auto Collection halts until space is cleared.

// services/resource.services.js
const db = require('../db');

const FIELD_CAP_HOURS = 16;
const AUTO_COLLECT_THRESHOLD = 0.90; // 90% capacity trigger

// Required workers per Town Hall level (TH 6 to 10)
const WORKER_REQUIREMENTS = {
  6: 600,
  7: 700,
  8: 800,
  9: 900,
  10: 1000
};

/**
 * Handles field storage calculation and Auto-Collection rules
 */
async function processCityAutoCollection(cityId) {
  const client = await db.getClient();
  try {
    await client.query('BEGIN');

    // 1. Fetch City Auto-Collect status, Town Hall level, and available workers
    const cityRes = await client.query(
      `SELECT auto_collect_enabled, town_hall_level, max_stockpile_capacity 
       FROM cities 
       WHERE id = $1 FOR UPDATE`,
      [cityId]
    );
    const city = cityRes.rows[0];

    // Gatekeeper checks: Enabled and TH Level 6+
    if (!city || !city.auto_collect_enabled || city.town_hall_level < 6) {
      await client.query('COMMIT');
      return;
    }

    // Worker reservation check (ensure town has enough workers for auto-collect)
    const reqWorkers = WORKER_REQUIREMENTS[Math.min(city.town_hall_level, 10)] || 600;
    const workerRes = await client.query(
      `SELECT amount FROM city_resources WHERE city_id = $1 AND resource_type = 'workers'`,
      [cityId]
    );
    const availableWorkers = Number(workerRes.rows[0]?.amount || 0);

    if (availableWorkers < reqWorkers) {
      // Not enough workers available to execute auto-collection
      await client.query('COMMIT');
      return;
    }

    // 2. Fetch City Production Resources
    const resources = await client.query(
      `SELECT resource_type, amount AS stockpile, uncollected_amount, hourly_production, last_collected_at 
       FROM city_resources 
       WHERE city_id = $1 AND resource_type != 'workers' FOR UPDATE`,
      [cityId]
    );

    const maxStockpileCapacity = Number(city.max_stockpile_capacity || 99999999);

    for (const res of resources.rows) {
      const hourlyProd = Number(res.hourly_production || 0);
      if (hourlyProd <= 0) continue;

      const maxFieldCap = hourlyProd * FIELD_CAP_HOURS;
      const autoCollectTrigger = maxFieldCap * AUTO_COLLECT_THRESHOLD;

      // Calculate accrued field storage based on elapsed time
      const now = new Date();
      const hoursPassed = (now - new Date(res.last_collected_at)) / (1000 * 60 * 60);
      const accrued = hourlyProd * hoursPassed;
      const currentFieldStored = Math.min(maxFieldCap, Number(res.uncollected_amount) + accrued);

      // Trigger auto-collection if threshold (90%) is reached
      if (currentFieldStored >= autoCollectTrigger) {
        const currentStockpile = Number(res.stockpile);

        // BOTTLENECK CHECK: Is the Central Stockpile / Warehouse full?
        if (currentStockpile >= maxStockpileCapacity) {
          // Stockpile is full: Auto-collection pauses, resources remain in field
          continue; 
        }

        // Calculate available deposit room in central stockpile
        const spaceAvailable = maxStockpileCapacity - currentStockpile;
        const amountToTransfer = Math.min(currentFieldStored, spaceAvailable);

        const newStockpile = currentStockpile + amountToTransfer;
        const remainingInField = currentFieldStored - amountToTransfer;

        // Update database state
        await client.query(
          `UPDATE city_resources 
           SET amount = $1, 
               uncollected_amount = $2, 
               last_collected_at = CURRENT_TIMESTAMP 
           WHERE city_id = $3 AND resource_type = $4`,
          [newStockpile, remainingInField, cityId, res.resource_type]
        );
      }
    }

    await client.query('COMMIT');
  } catch (err) {
    await client.query('ROLLBACK');
    console.error(`Auto collection error for city ${cityId}:`, err);
  } finally {
    client.release();
  }
}

module.exports = {
  processCityAutoCollection
};
